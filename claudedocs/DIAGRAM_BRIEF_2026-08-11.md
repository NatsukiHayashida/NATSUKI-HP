## 共通の前提（毎回これを一緒に貼る）

個人ポートフォリオサイトに載せる技術記事の**模式図の設計**をお願いします。
サイトは製造業（冷間鍛造の金型設計）のエンジニアのもので、デザインは
**ミニマル・エディトリアル**。機械製図の作法（細線・罫線・ハッチング）をモチーフにしています。

### いちばん大事な基準（これを満たせない案は採用できません）

**図から名称・ラベル・数値をすべて隠した状態で、次の4つが判別できること。**

1. 何と何を比較しているか
2. どこが問題か
3. 何が変化したか
4. 結論はどこか

文字を消すと意味がなくなる図は、模式図ではなく**フローチャート**です。
**形・位置・範囲・重なり・欠損**で結論を伝えてください。
とくに「結論を文章で大きく書く」のは無効です。その文章を消したら何も残らないためです。

### 出力してほしいもの（3点セット）

1. **構図の説明**（文章）：何をどこに置き、視線をどう動かすか
2. **SVG草案**（SVGのソースコード。**PNGや画像ファイルではなく、テキストのSVG**）
3. **凡例リスト**：名称 → 一行説明。**図が語れないことだけ**を書く（図を見れば分かることは書かない）

### PC用とスマホ用、構図を2つ

サイトはスマホでの閲覧が中心です。**横長の図を縮めると読めなくなる**ので、
**縦に組み替えた別構図**を必ず用意してください。

- PC用：横長（viewBox 例 `0 0 1000 470`）
- スマホ用：縦長（viewBox 例 `0 0 320 480`。**幅320で成立する構図**に組み直す）

「横のものを縦に並べ替えただけ」ではなく、狭い幅で読める構図にしてください。

### 色 — 明暗2つのテーマがあります

サイトには**ライトモードとダークモード**があり、利用者が切り替えます。
**決め打ちの色（`#242424` や `#f4f1ea` など）は使えません。** 明るい背景を前提に描くと、
ダークモードで「黒い画面に白いカードが浮いた」状態になります。

色は次の**3つの役割だけ**で組んでください。実際の値への置き換えはこちらで行います。

| 役割 | 草案での書き方 | 用途 |
|---|---|---|
| 線・文字 | `currentColor` | 線画のほぼ全部 |
| 背景・白抜き | `hsl(var(--background))` | 線を切る、面を抜く |
| 強調（朱） | `hsl(var(--primary))` | **1図につき1つの意味だけ** |

- **新しい色を足さない。** 青緑・グラデーション・紫は使わない
- **強調色に複数の意味を持たせない。**「欠陥」と「失敗側」と「悪化した数値」を
  全部同じ色にすると、その色を見ても何のことか決まりません
- 面を区別したいときは塗りつぶしではなく**ハッチング（斜線）**を使う（製図の断面表現）。
  塗り（`fill` + `opacity`）はダークモードで想定より強く出ます

### 図の中に文字を置かない

viewBoxごと縮むので、スマホで潰れます。**名称はHTMLでSVGの上に重ねます**（こちらで行います）。

- SVGの中には**文字を一切入れない**（見出し・ラベル・数値・「AI」などの文字も含む）
- そのかわり、**名前を置く余白を空けておいてください**。
  どこに何という名前を置くつもりかは、構図の説明に書いてください
- 番号バルーンだけを打って名称を凡例へ回すのも**禁止**です。
  図と凡例を往復させることになり、読むのに一手間かかります

### そのほか

- **矢印と文字を並べただけの図は禁止。** 形のあるものを線画で描く
- **処理の流れを箱で並べない。** 見せたいのは工程ではなく「何が消え、何が残ったか」。
  モデルやAIを箱として描く必要はありません
- カード・背景色ボックスは使わない。罫線と細線で構成する
- **数値・事実の創作は禁止。** 仕様に書かれた数値だけを使う。
  「粒を10個と8個並べて割合を表す」のように、根拠のない数を描くのも創作にあたります
- 会社名・製品名・人名・金額・社内パスは、仕様に書かれていなくても絶対に入れない。
  部品は実物ではなく**汎用の丸物**として描く

### 1. 「何が変わったか」が図から消えています（最重要）

### 2. ×と✓の記号を使わないでください

良否を記号で書いてしまうと、図が説明したことになりません
（記号を読んでいるだけで、絵は何も証明していない）。**両方とも削除してください。**

そもそもこの図の結論は「良い／悪い」ではありません。
**「欠陥が消えたか、残ったか」**です。それが絵で分かれば記号は要りません。

### 3. マスクは黒塗りではなく、外周の帯です（前回から未修正）

**(a) 色が違います。** いまは線と同じ濃い色の矩形（`opacity=".84"`）ですが、実際は
**背景の平均色で塗りつぶし**ています。黒塗りは
「モデルが黒い領域を新たな異常パターンとして学習するリスクを避けるため」
**意図的に避けた**手法なので、図が実際と反対のことを描いています。
`--bg`（背景色）で塗りつぶし、輪郭だけ細線で示してください。

**(b) 位置が違います。** いまは部品の中央あたりを四角が覆っていますが、実際は
**画像の外周を一定幅で塗りつぶす帯**（額縁状）です。
失敗の実体は「**端**のほうにあった欠陥が、外周の帯に飲み込まれて消えた」ことなので、
中央を覆う描き方だと因果が成立しません。

**(c) 部品が小さすぎます。ここが最大の問題です。**
いまは小さな部品が枠の中央に浮いていて、外周の帯とどこも接していません。
この描き方だと、帯が欠陥を消すことが**そもそも起こり得ません**。

実際の検査画像では、**部品は枠いっぱいに写っていて、その下の縁が帯の中まで入り込んで**います。
そして**欠陥は、その縁の上にありました**。だから帯に飲み込まれたのです。

寸法は下の「幾何の確定値」に書きました。

### 4. 「欠陥が消えた」パネルがありません

いまは黒い矩形が半透明なので、**欠陥が下に透けて見えたまま**です。
肝心の「消えた」が絵に出ていません。

第1経路には、**マスクを適用した後の絵**を1つ置いてください。
そこには部品はあるが、**欠陥印が無い**。これがこの経路の結論です。

### 5. 異常マップの「前」と「後」が判別できません

第2経路の右側（マスク後）で、**点線の枠の中に背景の点がまだ残って**います。
消す前なのか後なのかが読めません。

- マスク**前**：四隅に背景の点がある。部品の上に欠陥の反応がある
- マスク**後**：四隅の点が**無い**。欠陥の反応は**残っている**

また、いまは**朱の欠陥が点線の枠にかかって**いて、マスクされる側に見えます。
欠陥の反応は、除去範囲から**明確に外して**ください。

### 6. PC版も上下2段にしてください

いまPC版は左右比較ですが、**上下2段**にしてください。
スマホ版と同じ骨格になるので、読み方を2回学ばずに済みます。

### 7. スマホ版のレイアウトが重なっています

×／✓の丸が、小さな部品の列の最後に重なっています。
（1と2で両方とも削除されるので、結果的に解消するはずです）

### 8. 処理を表す箱は要りません

⊕の付いた箱が両経路にありますが、見せたいのは工程ではなく
「**何が消え、何が残ったか**」です。削除して構いません。

検査画像そのものと、マスクを適用した後の画像を実測して出した値です。

### 名称を隠したとき、こう読めるのが目標です

```
第1経路  部品に欠陥印がある → 外周の帯が欠陥印にかかる → 欠陥印が消えている
第2経路  部品に欠陥印がある → 四隅と欠陥に反応がある   → 四隅だけ消え、欠陥は残っている
```

強調色（朱）の使い方には2案あります。どちらでも構いませんが、**1つの意味に固定**してください。

- **案A：朱＝削る範囲**。第1経路は朱が欠陥印にかかり、第2経路はかからない。差が一目で出ます
- **案B：朱＝欠陥・異常信号**（いまの案）。この場合、削る範囲は `--line` の細線とハッチングで表す

### この図で使ってよい事実と数値

記事本文に書いてある範囲です。ここに無い数値は使わないでください。
**数値はHTML側に置くので、SVGには描かないでください**（余白だけ空けてください）。

| 事実 | 値 |
|---|---|
| マスクなし（ベースライン）の過検出率 | 44.2% |
| 入力画像にマスクをかけたときの過検出率 | 72.4% |
| 推論後の異常マップにマスクをかけたときの過検出率 | 20.8% |
| 背景の反応が出る場所 | 画像の四隅（部品が写っていない領域） |
| 制約 | 両方とも「不良品の見逃しゼロ」を守った上での比較 |

因果（凡例に書く内容。図には描かない）：
外周の帯が端の欠陥まで塗りつぶす → その不良品の異常スコアが下がる →
見逃しゼロを守るには閾値をその最低スコアまで下げるしかない →
閾値が下がった分だけ、それまで良品と判定できていた製品が不良側に落ちる。

### 上下を鏡像に描かないでください

「背景を除外するためにマスクをかける」という狙いは、2つの経路で同じです。
そこは揃えて構いません。**ただし、マスクの形が違います。**

- 入力側：画像の外周を一定幅で塗りつぶす、**固定の帯**（額縁の形）
- 推論後：部品の輪郭に沿って対象外を判定から外す、**部品の形に沿ったマスク**

上下2段を**同じ形のまま位置だけ変えた鏡像**として描くと、この違いが消えてしまいます。
**帯は額縁の形、輪郭沿いのマスクは部品の形**として、別々に描き分けてください。
言いたいのは次のことです。

> **入力を削ると、失うものがある。出力を削っても、失うものはない。**

## H-09. 評価指標の欠陥 ― 見ていたのは4象限のうち下の行だけ

外観検査AIの記事で、いちばん最初に置く図です。記事の主題そのものを担います。

### この図で言いたいこと

前任者が2年間使っていた評価指標は「不良品の検出率」だけでした。この指標には決定的な欠陥があります。
**すべての製品を不良と判定すれば、検出率100%が達成できてしまう。**

つまり「全品を不良と判定するだけの装置」と「実際に働いているモデル」が、
**この指標では同じ点数**になります。区別できません。

### 構図：2×2の盤面を2つ

判定結果は4通りに分かれます。盤面は縦2行×横2列で、**行が「実際にどちらだったか」**、
**列が「機械がどう判定したか」**です。

|  | 機械は「不良」と判定 | 機械は「良品」と判定 |
|---|---|---|
| **実際は良品**（上の行） | 良品を捨てた | 正しく通した |
| **実際は不良**（下の行） | 正しく止めた | **見逃した** |

旧指標（検出率）が見ていたのは、**下の行だけ**です。上の行は一切見ていません。

この盤面を2つ並べてください。**下の行は2つとも同じ絵になり、上の行だけが全く違う絵になります。**
それがこの図の結論です。

### 幾何の確定値（実際の評価結果の数字です）

各行を**横幅いっぱいの帯**として、左右の分割位置で内訳を表します。
**行ごとに合計100%**（上の行は良品283個ぶん、下の行は不良品178個ぶん）。

**盤面A：全品を「不良」と判定するだけの装置**

| 行 | 左（不良と判定） | 右（良品と判定） | 分割位置 |
|---|---|---|---|
| 上の行（実際は良品 283個） | 283個 | 0個 | **左100%**（分割線は右端） |
| 下の行（実際は不良 178個） | 178個 | 0個 | **左100%**（分割線は右端） |

**盤面B：実際に動かしたモデル**

| 行 | 左（不良と判定） | 右（良品と判定） | 分割位置 |
|---|---|---|---|
| 上の行（実際は良品 283個） | 125個 | 158個 | **左 44.2%** |
| 下の行（実際は不良 178個） | 178個 | 0個 | **左100%**（分割線は右端） |

**要点：下の行は A も B も左100%で、完全に同じ絵になります。** ここが狙いです。
上の行だけが「全部左」と「44:56」で違う。**この差を旧指標は見ていませんでした。**

**1つの盤面を `320 × 220` で描く場合**（縮尺は変えてよいが比率は変えない）：

| もの | 値 |
|---|---|
| 盤面の外枠 | `320 × 220` |
| 行の境界 | `y = 110`（上下同じ高さ） |
| 上の行の分割線 | 盤面A：`x = 320`（右端）／盤面B：`x = 141` |
| 下の行の分割線 | 両方とも `x = 320`（右端） |
| 「見ていた範囲」の囲み | **下の行の全体**（`y 110..220` の帯）を囲む |

### 強調色（朱）の使い方

**朱は「旧指標が見ていた範囲」だけに使ってください。** 1つの意味に固定します。
下の行を囲むブラケット（角括弧）と、その行の罫線だけを朱にする。
良否・正誤・多少には朱を使わないでください。

「見ていなかった上の行」は、朱を使わずに**細線とハッチングの有無**で表してください。

### 名称を隠したとき、こう読めるのが目標です

```
盤面が2つある。下の行は2つとも同じ形。上の行だけ形が違う。
朱の囲みは下の行にしかかかっていない。
→ 違いが出ている場所を、囲みが見ていない。
```

### 使ってよい事実と数値

**数値はHTML側に置くので、SVGには描かないでください**（余白だけ空けてください）。

| 事実 | 値 |
|---|---|
| テストに使った画像 | 461枚（良品283枚 / 不良品178枚） |
| 旧指標（検出率）の値 | 盤面A・盤面Bとも **100%** |
| 盤面Bで良品を誤って捨てた数 | 125枚（44.2%） |
| 盤面Aで良品を誤って捨てた数 | 283枚（100%） |
| 見逃し | どちらも0枚 |

### やらないでほしいこと

- ROC曲線・F1・AUCを図に入れない。**この図の結論は「下の行しか見ていなかった」の1点だけ**です
- 盤面を装置や機械として描かない。**罫線で区切った盤面**です
- ✓や×の記号を使わない

## H-10. ドメインシフト ― 撮った日が違うだけで、良品が不良より「不良らしく」なる

同じ記事の後半、いちばん大きな壁として書いている場面の図です。

### この図で言いたいこと

同じ検査対象の**良品**でも、**撮影した日（照明・カメラ・治具の状態）が変わっただけ**で、
モデルが出す異常スコアが跳ね上がります。どのくらい跳ね上がったかというと、
**別の日に撮った良品100枚は、同じ日に撮った不良品の6割よりも高いスコア**になりました。

良品のほうが、不良品より「不良らしく」出ている。閾値をどこに置いても分離できません。

### 構図：1本の横軸に、3つの群を並べる

横軸は**異常スコア**（左が低い＝正常らしい、右が高い＝異常らしい）。
軸は1本だけにして、その上に**3つの帯（レーン）**を上から順に置いてください。

1. **同じ日に撮った良品**（241個）
2. **同じ日に撮った不良品**（178個）
3. **別の日に撮った良品**（100個）

**1番目と3番目は、どちらも「良品」です。同じ形の印で描いてください。**
2番目だけ違う形（朱）にします。**同じ印が軸の両端に分かれること**が、この図の全てです。

### 幾何の確定値（実測値です。位置を動かさないでください）

軸の範囲を **0.20 〜 0.95** とし、その左端を `x=0`、右端を `x=1000` とした場合の値です。

| 群 | 実測のスコア範囲 | 軸上の位置（0〜1000） |
|---|---|---|
| 同じ日の良品（241個） | 0.243 〜 0.364 | **x 57 〜 218** |
| 同じ日の不良品（178個） | 0.323 〜 0.865 | **x 164 〜 887**（中央値は x 388） |
| **別の日の良品（100個）** | 0.515 〜 0.736 | **x 419 〜 714**（中央値は x 563） |
| 閾値（見逃しゼロで決まる位置） | 0.323 | **x 164** |

この配置から、次が自動的に成り立ちます。**そう見えるように描いてください。**

- 別の日の良品（x 419〜714）は、**閾値 x164 より完全に右**。100個すべてが不良と判定される
- 別の日の良品の左端 x419 は、**不良品の分布の約6割の地点**。
  つまり**不良品178個のうち107個が、別の日の良品より左（＝より正常らしい）**にいる
- 同じ日の良品（x 57〜218）と別の日の良品（x 419〜714）は、**まったく重ならない**

**印の描き方**：群ごとに、実測の範囲の中に印を散らしてください。
個数は多いので1個ずつ描かなくて構いませんが、**分布の濃さ（中央値のあたりが濃い）**を出してください。
**根拠のない個数を数えられる形で描かないこと**（例：ちょうど10個並べる、など）。

### 強調色（朱）の使い方

**朱は「不良品」だけに使ってください。** 1つの意味に固定します。
良品は2つの群とも `--line`（線の色）で、**同じ印**にしてください。
閾値の線は朱にしないこと（朱が2つの意味を持つため）。破線か、太めの細線で表してください。

### 名称を隠したとき、こう読めるのが目標です

```
同じ形の印が、軸の左端と真ん中より右の2か所に分かれている。
朱の群は左から右へ長く広がっていて、その右寄りの位置に、
左端にいたはずの形の印が入り込んでいる。
→ 同じものが、条件によって反対側へ移った。
```

### スマホ用

軸を**縦**にして、上が低スコア・下が高スコアにしてもよいです。
横のまま縮めると印が潰れるので、**幅320で読める構図**に組み直してください。
3つの群を横に並べる（軸が縦、群が横に3列）と、幅が足りるはずです。

### 使ってよい事実と数値

**数値はHTML側に置くので、SVGには描かないでください。**

| 事実 | 値 |
|---|---|
| 別の日に撮った良品 | 100枚すべてが不良と判定された（誤検出100%） |
| 同じ日の不良品のうち、別の日の良品より低いスコアだったもの | 178枚中107枚（60%） |
| 同じ日のデータでのAUC | 0.999 |
| 平均輝度 | 学習データ140 に対し、別の日のデータ167 |
| 輝度を正規化して再学習した結果 | それでも100枚中100枚が誤検出 |

### やらないでほしいこと

- カメラ・照明・治具などの装置を描かない。**軸と印だけ**でよい
- ヒストグラムの棒グラフにしない。**位置そのものが結論**なので、印の位置で見せる
- 「日付」を絵で表そうとしない（カレンダー等）。群を分けるのは印の位置だけでよい
