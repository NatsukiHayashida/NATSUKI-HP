## 図にしてよいかの判定

**図から名称・ラベル・数値をすべて隠して、次の4つが判別できること。**

1. 何と何を比較しているか
2. どこが問題か
3. 何が変化したか
4. 結論はどこか

これを机上で通せない場所は、**図にしない**。文字を消すと意味がなくなる図は模式図ではなく、
本文を絵に描き写しただけのものになる。過去に7枚作って全部これで落ちている。

もう一つ、**同じくらい大事なこと**がある。

> **幾何（位置・大きさ・比率）は、こちらが記録から実測して数値で確定してから渡す。**

「端のほうにある」「大きく occupying している」といった**言葉で渡すと、必ず別の絵が返ってくる**。
H-06 と H-07 は2回続けてこれで落ちた。実画像を実測して座標で渡した H-07R は一度で通った。
**依頼を出す前に、必ず元プロジェクトの記録に当たること。**

## 3. H-11 19.6時間の内訳（CAD自動化）

**場所**：「時間を食っていたのは、作業ではなかった」

**言いたいこと**：5日間19.6時間のうち、**手戻り・是正・復旧が13.8時間（70%）**。
正味の新しい作業は5.8時間しかない。しかも記録の25%は計測そのものが失われている。

**なぜ図にする価値があるか**：これは**面積比がそのまま結論**になる。
一本の帯を70:30に割るだけで、名称を隠しても「大きい方が問題」が読める。
数字を読ませる必要がない、いちばん図に向いた題材。

**名称を隠したときの読み**：一本の帯が大小2つに割れている。大きい方にハッチング（＝失われた側）。
帯の一部が破線（＝計測できていない範囲）。

**幾何**：記事に数値がある（13.8h / 5.8h / 計測欠損25%）。
**ただし内訳の根拠となる記録が `~/work/pj-claude-fusion/` にあるはずなので、依頼前に確認すること。**
「38件」の分類が取れるなら、帯をさらに分けられる。

## 4. H-12 入口だけが細った（花製作所）

**場所**：「分解して分かったこと」〜「結論 ― 直すべきはサイトではなかった」

**言いたいこと**：全面リプレイスの設計まで進めたが、9,047件を分解したら
**サイトの中（転換率・リピート層）は健全で、細っていたのは入口だけ**だった。だから作らなかった。

**なぜ図にする価値があるか**：この記事の主題は「作らないという判断」で、
その根拠がこの一枚に集約できる。**上が細くなった漏斗**という形そのものが結論になる。

**名称を隠したときの読み**：2つの漏斗が並んでいる。上の口の幅だけが違い、
下の段の**くびれ方（比率）は同じ**。つまり細くなったのは入口だけ。

**幾何**：**要実測。** 記事にあるのは 9,047件 / 2,174人 / 617人 / 118人 / SNSタップ28.5%減 / 転換率約2.9%。
**前期間と後期間それぞれの数値が要る**（いまは減少率しかない）。
`~/work/hana/` の分析結果に当たって、両期間の実数を出してから依頼すること。

**伏字の注意**：店名・商品名・売上実額は出さない。**件数と人数と割合だけ**にする。

## 5. H-13 検査が覆っていた範囲（CAD自動化）

**場所**：「一番の失敗 ― 全部の検査に合格した図面が、加工できなかった」

**言いたいこと**：自動検査は通っていたが、**図面として必要な範囲を覆いきれていなかった**。
合格＝正しい、ではない。

**名称を隠したときの読み**：大きな枠の中に小さな枠がある。小さな枠の外側に、
覆えていない領域が帯として残る。追加した枠がその帯まで届いている。

**幾何**：**要実測。** 何項目の検査があり、図面として必要な項目が何項目だったのか、
その差分は何だったのかを `~/work/pj-claude-fusion/knowledge/` で確認する。
**面積比を根拠なく描くと事実の創作になる**ので、項目数が取れないなら図にしない。

**注意**：`h-05-gate-coverage-gap.svg` として一度作って撤去した。
撤去理由は「小記号と番号が多すぎて凡例と往復させていた」こと。**外枠と内枠だけにする。**

## 6. H-14 位置ずれが欠陥より大きい（外観検査AI）

**場所**：「教師ありから、教師なしへ」の末尾

**言いたいこと**：良品同士の平均ピクセル差が8.7、良品と不良品の差が13.2〜14.9。
**差の大半は欠陥ではなく位置ずれ**なので、単純な画素比較では原理的に届かない。

**名称を隠したときの読み**：2枚の輪郭をわずかにずらして重ねると、
**輪郭全周に太い差の帯**ができる。欠陥はその中の**小さな点**でしかない。帯のほうが明らかに大きい。

**幾何**：数値は記事にある。ずれ量と欠陥の大きさの比は、
`~/work/iidzka-inspection/` の実画像から実測して確定させること。

**優先度が低い理由**：記事が既に長い。上の5枚を入れてから、まだ要ると思ったら作る。

## 依頼を出す手順

2. `claudedocs/DIAGRAM_BRIEF_2026-08-11.md` に `## H-xx. 見出し` の節を足す。
   書き方は同ファイルの「参考：完了した依頼（H-07R）」に倣う
3. `python3 scripts/build-handoff.py` で `_handoff/` を生成
4. スマホから `https://node.taile73628.ts.net:8443/NATSUKI-HP/_handoff/index.html` を開き、
   「共通の前提」＋その図の節をまるごと貼る。**1回の依頼につき1図**

6. 通ったら React 化して `app/components/diagrams/` に置き、
   `app/components/article-diagrams.tsx` に登録、MDX に `<figure data-diagram="キー">` を書く
