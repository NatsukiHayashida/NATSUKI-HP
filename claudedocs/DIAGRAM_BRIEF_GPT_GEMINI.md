# 図案依頼書 — GPT / Gemini 用（H-01〜H-05）

**使い方**：この文書の「共通の前提」＋依頼したい図1件分（H-0x節）をまるごと
ChatGPT / Gemini に貼り付けて、図案を出してもらう。
**1回の依頼につき1図**（記事1本ずつ完成させる運用のため。着手順は H-01 → H-02 → H-03 → H-04 → H-05）。

返ってきた図案は Claude Code に渡す。React コンポーネント化・規約への最終適合・
サイトへの組み込みは Claude Code 側で行うので、**GPT / Gemini の成果物は「構図とSVG草案」まででよい**。

## 共通の前提（毎回これを一緒に貼る）

あなたには、個人ポートフォリオサイトに載せる技術記事の**模式図の設計**をお願いします。
サイトは製造業（冷間鍛造の金型設計）のエンジニアのもので、デザインは
**ミニマル・エディトリアル**：白/黒基調＋アクセントは朱（バーミリオン）1色のみ、
機械製図の作法（細線・罫線・ハッチング・部品表）をモチーフにしています。

### 出力してほしいもの（3点セット）

1. **構図の説明**（文章）：何をどこに置き、視線をどう動かすか
2. **SVG草案**（インラインSVGコード）：下の制約に従うこと
3. **凡例リスト**：番号 → 名称 → 一行説明（製図の部品表にあたる。HTML側に置くため図とは別に）

### SVGの制約（違反すると作り直しになる）

- **矢印と文字を並べただけの図は禁止**。形のあるものを線画で描く（装置・書類・盤面・分布の山など）
- **SVGの中に説明文・ラベル文字を入れない**。スマホで潰れるため。
  図の中に置いてよい文字は**番号バルーン（①②…に相当する丸＋数字）だけ**。
  名称・説明はすべて凡例リストへ出す
- 色は `currentColor`（線・文字）と `hsl(var(--background))`（白抜き）だけを使い、
  強調したい**1系統**にのみ `text-primary`（朱）を使う。**新しい色・グラデーション・紫は禁止**
- カード・背景色ボックスは使わない。罫線と細線で構成する
- 塗りつぶしは避け、面を区別したいときは**ハッチング（斜線）**を使う（製図の断面表現に合わせる）
- viewBox は横長（例 `0 0 1000 460` 程度）。スマホでは縦積みに組み替える前提なので、
  可能なら「モバイルではどう縦に組み替えるか」も一言添える
- **図に含める内容は、下の仕様に書かれた範囲に限る**。数値・事実の創作は禁止。
  会社名・製品名・人名・金額・社内パスは仕様に書かれていなくても絶対に入れない

## H-01. 評価指標の欠陥 ― 混同行列で「何を見ていなかったか」を示す

- **記事の文脈**：外観検査AIの内製開発。引き継いだシステムは評価指標が「不良品の検出率」だけだった。
  この指標では「すべての製品を不良と判定すれば検出率100%・見逃しゼロ」が達成できてしまう。
  精度が出ないのではなく、**精度を測る道具が壊れていた**。だから2年分の試行が事後検証すらできなかった
- **図の種類**：概念図（混同行列 2×2）
- **含める要素**：
  - 2×2の盤面（真陽性・偽陰性・偽陽性・真陰性）
  - 旧指標が見ていた範囲の囲い（4象限のうち2象限しか見ていない）
  - 見ていなかった2象限は無彩色・無印のまま残す
  - 「全品を不良と判定した場合」の極端値を同じ盤面に重ねる表現
  - 新しく足した指標（F1・ROC・AUC）がどの象限を使うかの対応
- **読者に理解してほしいこと**：指標が見ている範囲の欠落。2象限の盲点
- **数値**：使わない（記号と塗り分けのみ）

## H-01R. H-01の修正依頼 ― 受け取った草案の直し

先にいただいた `h-01-confusion-matrix.svg` を実際に描画して確認しました。
構図の方向性（盤面の左に極端値、右へ指標）は活かしたいので、下の点を直してください。
**SVGの再提出に加えて、凡例リストを必ずテキストで（.md か .txt で）別ファイルとして保存**してください。

■ 直してほしいこと（重要な順）

1. 凡例リストが届いていません。SVGだけでは番号バルーン9個の意味が分からず、実装できません。
   番号 → 名称 → 一行説明 を、01〜09すべてについてテキストで出してください
2. 色の指定が違います。`hsl(var(--vermilion))` はこのサイトに存在しません。
   朱は `hsl(var(--primary))` を使ってください（背景は `hsl(var(--background))` で正しい）
3. 右下の3つの計器（07・08・09）が壊れています。viewBoxの下端からはみ出し、
   3つが階段状にずれて重なり、針が数字に重なっています。
   位置を盤面の右側に整列させ、すべてviewBox内（余白を各辺40以上）に収めてください
4. 破線のコネクタ（盤面から右下へ流れている線）が、どこへ何をつないでいるのか読めません。
   本数を減らし、始点と終点が明確な線だけにしてください
5. ハッチングの位置が主旨と矛盾しています。旧指標が見ていたのは左列の2象限（01と03）のはずですが、
   ハッチングは01だけに入っています。**見ていた2象限を同じ表現で示し、
   見ていなかった2象限は無印のまま**にしてください
6. 05のブラケットが盤面の全幅を覆っているため、「4象限のうち2つしか見ていなかった」という
   主旨と逆に読めます。旧指標の作用範囲だけを囲ってください

■ 全体として

この図で一目で分かってほしいのは **「4象限のうち2つしか見ていなかった」** という一点です。
いま届いた草案は、線と枠は整っているものの、この一点が読み取れません。
迷ったら要素を減らし、盤面と「見ていた範囲の囲い」を主役にしてください。

## H-02. マスクをかける場所で結果が逆転する

- **記事の文脈**：同じ外観検査AI。検査対象外の領域を隠すマスクを、
  **入力画像側**に入れたら過検出率72.4%に悪化、**推論後の異常マップ側**に入れたら20.8%に改善した。
  同じ部品でも、パイプラインのどこに挿すかで結果が正反対になる。
  入力側に入れると欠陥の情報まで削られてしまうのが原因
- **図の種類**：Before / After × データフロー（2本並置）
- **含める要素**：
  - 「画像 → 前処理 → モデル → 異常マップ → 判定」という1本の流れを上下2本並べる
  - マスクの挿入位置だけが上下で違う
  - 各系列の末尾に結果（72.4% / 20.8%）※数値バルーンではなく凡例側でもよい
  - 入力側では欠陥情報まで削られることを示す差分表現
- **読者に理解してほしいこと**：打ち手の良し悪しではなく、**打ち手を置く場所**の問題
- **使ってよい数値**：72.4% / 20.8% のみ

## H-03. ドメインシフト ― 分離できないという事実を数直線で見せる

- **記事の文脈**：同じ外観検査AI。学習と同じ日に撮った画像ではAUC 0.999で分離できたが、
  別セッションで撮った良品100枚は異常スコアの**最小値が0.5385**。
  テストで使っていた良品の**最大値は0.38**。閾値をどこに動かしても分離できない。
  だから撮像条件を固定する方向へ舵を切った
- **図の種類**：数直線（スコア軸上の位置関係＋閾値の帯）
- **含める要素**：
  - スコアの数直線
  - 学習時の良品と不良品（閾値で分離できている状態）
  - 別セッションの良品100枚（完全に不良品側へ移動している）
  - 閾値線をどこに置いても両立しないことを示す帯
- **読者に理解してほしいこと**：0.38 < 0.5385 という位置関係そのものが結論
- **使ってよい数値**：0.38 / 0.5385 / AUC 0.999。
  **分布の形は記録がないため描かない**。最小値・最大値・閾値だけの数直線に落とすこと

## H-04. 19.6時間の内訳 ― 手戻りが70%だったという事実

- **記事の文脈**：CAD操作のAI自動化。5日間38件の作業記録19.6時間を分解したら、
  手戻り・是正・復旧が13.8時間で全体の70%。正味の新作業は5.8時間だけだった。
  ただし記録の25%は計測欠損で概算。遅かったのは作業ではなく、
  正しさを確定させずに作り始めて壊すループだった
- **図の種類**：積み上げ帯（構成比）＋不確かさの表現
- **含める要素**：
  - 19.6時間の帯を「手戻り13.8h」「正味5.8h」の2区分に分ける
  - 計測欠損25%を**ハッチングで重ねて**無視できなくする（誠実さの表現）
  - 発端のエピソード「穴あけ1つに35分・12万トークン」を図の脇に小さく置ける構成
- **読者に理解してほしいこと**：時間を食っていたのは作業ではなく手戻りのループ
- **使ってよい数値**：19.6h / 13.8h / 5.8h / 70% / 25% / 35分 / 12万トークン

## H-05. 「門は、門が見ている対象しか守らない」

- **記事の文脈**：同じCAD自動化。用意した検査ゲートは全て合格したのに、
  出てきた図面は投影図が1面しかなく加工できなかった。一般公差・面粗さ・面取りの指示も抜けていた。
  検査が見ている範囲と、図面として成立するのに必要な範囲がずれていた。
  後から「原本と同じ物差しで測るゲート」を足した。同じ構造の失敗（外形線の抜け）が2回起きている
- **図の種類**：概念図（範囲の包含関係）
- **含める要素**：
  - 外側の枠＝図面として成立するために必要な条件の全体
  - 内側の枠＝用意した検査ゲートが見ていた範囲
  - その差分領域に、抜けたもの（投影図の数・一般公差・面粗さ・面取り・外形線）を番号バルーンで配置
  - 後から足したゲートが差分をどこまで覆うかの表現
- **読者に理解してほしいこと**：検査に通ることと正しいことは別物
- **数値**：使わない
